# 一覧ビュー（Issue #12）設計

2026-11-05

## 目的

仕分け元フォルダに大量の画像がある中から目当ての 1 枚を探したいとき、読み込んだ画像を一覧で見渡せるようにする。一覧で画像を選ぶと 1 枚表示（既存の仕分け画面）に切り替わり、その画像が「現在の画像」になってそのまま振り分けキーで移動できる。

## 決定事項（ユーザー確認済み）

- 一覧には**全画像**を出す。処理済み（移動・削除予定）は薄く表示し、移動先などのラベルを付ける。処理済みは選んでも開けない（取り消しで戻す）
- 開き方は**ボタン＋設定可能なキー**。`[keys] toggle_grid`（既定 `Ctrl+Shift+L`）を追加し、設定画面と TOML から変更できる
- **ファイル名の絞り込み欄**を付ける（部分一致、大文字小文字を区別しない）
- **サムネイルの大きさを切り替えられる**。スライダーで自由に変えられ、キーで段階的にも変えられる（後述）
- キーボードだけで操作できること（要件「キーボードだけで仕分けが完結する」）
- 一覧は表示モード（サイドバー／全画面）とは別の一時的な画面で、設定には保存しない

## サムネイルの返し方

一覧用のサムネイル専用キャッシュを追加する（採用）。

- 既存の `thumb` ルートは 2560px のプレビューごと 24 枚のキャッシュに入れるため、一覧で使うと先読みが押し出され、1 枚表示に戻ったときに待ちが出る。メモリも増える
- 新しいルート `lumi://grid/{generation}/{index}` を追加し、一覧用のサムネイルだけを別の LRU キャッシュに持つ
- 一覧用サムネイルの大きさは長辺 480px（`GRID_THUMB_MAX`）。タイルを最大（360px）にしても、また高 DPI の画面で中くらいの大きさにしてもぼやけないようにする。フィルムストリップ用の 240px（`THUMB_MAX`）とは別に作る
- キャッシュの容量は 1000 枚（1 枚 30〜50 KB で 40 MB 程度）
- 一覧のサムネイルのデコードは同時実行数を制限する（3 程度）。プロトコルの処理は要求ごとにスレッドを立てるため、一覧で数十枚が同時に要求されると原寸デコードが並列に走り、メモリを大きく消費するのを防ぐ
- 仕分け元を読み直したとき（`start_session`）にプレビュー用キャッシュと一緒に破棄する
- キャッシュのキーは元の場所のパス（既存のプレビュー用キャッシュと同じ）。読み込むファイルは今ある場所（`state::location`）

## Rust

### `list_items` コマンド（`commands.rs`）

`fileops::Session` は変更しない。現在のセッションの全画像を並び順のまま返す。

```ts
interface GridItem {
  index: number;
  name: string;
  state: "pending" | "skipped" | "moved" | "deleted";
  /** moved: 振り分け先の表示名 / deleted: "削除予定" / それ以外: null */
  label: string | null;
}
interface GridList { generation: number; current: number | null; items: GridItem[] }
```

- `moved` のラベルは、移動先の親フォルダが設定の振り分け先と一致すればその表示名（`Target::display_name`）、一致しなければフォルダ名
- `Trashed` と `Marked` はどちらも `deleted`（「削除予定」）
- セッションがなければ既存のコマンドと同じエラー

### サムネイルキャッシュ（`decoder/`）

- サムネイルだけを持つ LRU キャッシュ。同じ画像への同時要求でデコードを 1 回にする挙動、失敗をエラーとして覚える挙動は `PreviewCache` と同じにする（共通化できるなら値の型でジェネリックにする）
- デコード時の同時実行数を制限するセマフォ（`Mutex<usize>` ＋ `Condvar`）

### `grid` ルート（`protocol.rs`）

- `/grid/{generation}/{index}`。古い generation・範囲外は既存どおりエラー（404）

### 設定（`config/`）

- `ActionKeys` に `toggle_grid`（既定 `Ctrl+Shift+L`）。`Ctrl+Shift+G` は WebView の検索の予約キーなので避ける
- 既存の設定ファイルに項目がなければ既定値を補う（`toggle_paths` 追加時と同じ）
- 重複チェックの対象に含める（「一覧表示の切り替え」）

## 画面

### 画面の切り替え

- `Screen` に `"grid"` を追加。新規ファイル `src/views/grid.ts`
- 開く: 仕分け画面のトップバーの一覧ボタン（全画面モードでは右上のボタン）、または `toggle_grid` キー
- 閉じる: `Escape` または `toggle_grid` で仕分け画面に戻る。Enter／クリックで画像を開いたときも仕分け画面に戻る
- 開くたびに `list_items` で最新の状態を取得する
- 同名ファイルの確認中（`session.conflict`）は開かない

### 表示

- ヘッダー: 「一覧」の見出し、絞り込み欄、件数（`12 / 340 枚`）、閉じるボタン
- タイル: サムネイル（`loading="lazy"`）＋ファイル名。現在の画像に印、保留に「保留」バッジ、処理済みは薄く表示してラベル（振り分け先名／削除予定）
- 並びはセッションの並び（設定の並び順）と同じ
- 開いた時点では現在の画像を選択し、そこまでスクロールする（すべて処理済みなら先頭）
- タイルは一覧を開いたとき（と絞り込みを変えたとき）だけ作る。選択の移動ではクラスとスクロールだけを更新し、画像を読み直さない
- サムネイルを読めなかったタイルはアイコンを出す

### サムネイルの大きさ

- 一覧はスクロールするので、画像が多くてもタイルが小さくなることはない。タイルの幅（＝1 行の枚数）を利用者が変えられるようにする
- ヘッダーにスライダーを置き、タイルの幅を 96〜360px の範囲で自由に変えられる（CSS 変数 `--grid-tile` を書き換えるだけで、サムネイルは読み直さない）
- キーとホイールで段階的にも変えられる: 小 96 / 中 160 / 大 240 / 特大 360px。今の大きさの次の段階へ移る
- 大きさは次回も使う（サイドバーの幅と同じく `localStorage` に保存する。設定ファイルには書かない）。既定は「中」(160px)
- 大きさを変えても選択中の画像が画面内に残るようにスクロールする

### キー操作

| キー | 動作 |
| --- | --- |
| ← → ↑ ↓ | 選択を移動（↑↓ は 1 行分。列数は描画結果から求める） |
| PageUp / PageDown | 1 画面分 |
| Home / End | 先頭 / 末尾 |
| Enter | 選択した画像を開く |
| Ctrl+F | 絞り込み欄にフォーカス |
| Ctrl+= / Ctrl+; / Ctrl+NumAdd（Shift 付きも可） | サムネイルを 1 段階大きく（JIS 配列の「+」は `;` のキー） |
| Ctrl+- / Ctrl+NumSubtract | サムネイルを 1 段階小さく |
| Ctrl+0 | サムネイルを既定の大きさに戻す |
| Ctrl+ホイール | サムネイルを 1 段階ずつ拡大・縮小 |
| 絞り込み欄で Enter / ↓ | 一覧に戻る（絞り込み結果の先頭を選択） |
| 絞り込み欄で Esc | 欄から抜ける（既存の挙動） |
| Esc / `toggle_grid` | 仕分け画面に戻る |

- 開く操作は `actions.jumpTo(index)`。処理済みの画像は開かず、「この画像はすでに振り分け済みです（取り消しで戻せます）」と表示する
- 一覧画面では振り分けキー・削除・スキップは受け付けない（誤操作防止）
- Ctrl+= / Ctrl+- / Ctrl+0 は WebView の拡大縮小キー。Tauri の `zoomHotkeysEnabled` は既定で無効で、さらに `isBrowserKey` で既定動作を止めているので、一覧の拡大縮小に使える

## エラー処理

- `list_items` が失敗したらトーストを出して仕分け画面のまま
- 一覧表示中にセッションが変わった（generation が変わった）ら閉じる
